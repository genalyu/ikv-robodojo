# RGB Max teacher and periodic DM05 history selection

`RGBMaxClient(task, root, pooling="mean")` registers each observed three-camera RGB atlas in frame order and sends the complete registered prefix to the Qwen3.8-Max compatible API. The root supplies `private/bailian.key` and `prompt_visual.txt`; credentials are never written to requests or results. Every API query retains its frame mapping, raw responses, usage, exact block assignment and decoded scores. API/validation errors raise rather than falling back to fabricated scores.

The teacher codec assigns integers to every frame/camera/8x8 patch through a default and ordered half-open cuboids. For DM05 history, register the same square-padded RGB used by native preprocessing. Head-camera 2x2 groups map to the native 4x4 grid by configurable mean or maximum. Wrist views supply context; they do not create extra history KV. Current three-view native dense KV remain separate.

`PeriodicRGBBank(..., interval=4)` archives every real native KV update. At an interval boundary it scores the complete historical candidate set and recalls the highest-ranked actual KV. Between boundaries, only resident or genuinely new IDs are eligible; refreshes cannot silently resurrect evicted patches. By default, capacity deficits evict the lowest last-Qwen-score resident KV first. New, unscored evidence is protected until the next real Qwen scoring event. Ties prefer newer evidence. Score updates and cadence publish only after a successful transaction. An explicit intermediate_policy="fifo" retains the previous comparison behavior. Cadence advances only on a successful transaction commit. Source IDs remain temporally sorted. No VLM reread or task-specific actions are introduced by this selector.

The caller owns episode reset and must construct a fresh bank/client per episode. Registered frames must be contiguous and causal. Current implementation is intended for prefixes below the provider image-count limit; it never silently drops history. Larger histories require a lossless full-resolution packet transport before use.

The optional image_size=448 preserves the native preprocessed RGB size for the scorer instead of reducing it to256. It changes only teacher RGB transport resolution; the8x8 score grid and4x4 KV mapping remain unchanged. Record image size and actual API token usage when comparing it.

`minimum_score=20` optionally enables scheduled Qwen scoring even before the archive fills. This uses the documented0–19 weak/superseded band to suppress weak historical KV rather than waiting until320 tokens force a first intervention. `minimum_score=0` preserves overflow-only scoring. Unscored new rows remain protected between scoring events, filtered rows stay in the CPU archive, and a later genuine scoring event may recall them. Record the earlier scoring cadence, selected count, native termination cause and API cost; this is an experimental retention option, not a success guarantee.
